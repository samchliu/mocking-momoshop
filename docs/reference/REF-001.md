# REF-001：題目 — Frontend Take Home Evaluation（摘要）

> 原始 PDF 不納入 repo（避免公開題目原文），此處只記錄與決策相關的重點。規格以權威文件（REQ／BR／ADR）為準。

## 摘要

**評估目的**：架構與可維護性、Production／Delivery Thinking、AI／Agent 協作與工程判斷。更重視「問題拆解／系統演進」與「Tradeoff／Delivery Quality」，而非功能完成度。

**時程**

- Phase 1 — Design／Planning（約 1 小時）：可與 AI 討論架構、workflow、實作策略；建議保留設計筆記、取捨分析與 AI／Agent 協作紀錄。
- Phase 2 — Implementation（約 1–2 小時）：以第一個 commit 到最後一個 commit（或第一個 commit 後約 120 分鐘內）為主要參考。需說明優先順序與刻意不做的部分；時間不足時優先完成核心架構與設計方向。

**題目（二選一）**

- **A. Mocking momoshop**：參考 momo 建立電商網站，純前端、不呼叫真實網站 API。建議路由至少一個：`/`、`/search/...`、`/goods/...`、`/discover/...`、`/live/...`。架構、路由、狀態、渲染策略、mock 資料結構自由決定。
  - 考核：實作結果與真實網站的差異；開發流程規劃與 Agent 協作效率評估／分析。
  - Bonus：Human-Agent Iteration Architecture；Validation／Observability Thinking。
- B. Merchant Card Showroom：商品卡展示、調整介面（瀏覽器端持久化）、可嵌入範例；Bonus 為可重用架構、Schema／Plugin、狀態一致性。

**技術限制**：不限框架與工具（AI 工具、OSS 皆可）。重視工程判斷、可維護性、AI／Agent 監督能力；不追求完整商業功能或 UI 精緻度。

**提交**：原始碼（含 git history）、Git History（含 Agent Co-authored 紀錄）、README／Docs／架構與取捨說明／後續演進方向。「請將自己視為此系統的長期維護者，而不只是功能實作者。」
