# EXP-001：選題與範圍探索

## 最初的想法

題目 A（Mocking momoshop）與 B（Card Showroom）二選一。實作時間約 120 分鐘，評分更重視架構、取捨、交付品質與 AI 監督，而非功能完成度（REF-001）。

## 問題假設

評審想看的是「一個可以被長期維護、可以被 agent 安全地持續演進的前端系統」，而不是像素級復刻。

## 使用者與利害關係人

| 角色                        | 在意                                            |
| --------------------------- | ----------------------------------------------- |
| 評審（Senior/Principal FE） | 架構判斷、取捨說明、git history、AI 監督證據    |
| 假想的終端使用者            | 找商品（搜尋、篩選、排序）→ 看商品 → 加入購物車 |
| 未來的維護者（人或 agent）  | 知識在哪裡、為什麼這樣做、改了會影響什麼        |

## 假設

| #   | 假設                                                                                                              | 信心       | 驗證方式                      |
| --- | ----------------------------------------------------------------------------------------------------------------- | ---------- | ----------------------------- |
| H1  | 選 A 比 B 更能展現評審要的能力：A 的 bonus（Human-Agent Iteration、Validation/Observability）與知識庫流程直接對應 | supported  | 對照 REF-001 的 bonus 項目    |
| H2  | 「搜尋 → 商品」這條動線最能展示前端工程判斷（URL 狀態、競態、快取、錯誤處理），比首頁的視覺區塊更有價值           | supported  | REF-002：搜尋頁的互動密度最高 |
| H3  | 3 個路由（`/`、`/search/:keyword`、`/goods/:id`）是 120 分鐘內可交付的上限；`/discover`、`/live` 不做             | hypothesis | 實作後以 RPT-001 回顧         |
| H4  | 與實站的差異應「刻意且有記錄」，而不是追求相似度                                                                  | hypothesis | 評審回饋（on-site）           |

## 未知事項

- 評審對「與真實網站差異」的權重：是比視覺，還是比行為？→ 處理方式：行為優先（搜尋語意、價格規則、URL），視覺只做到版面結構與品牌色。

## 原型目標

不另做原型；直接以可運作的系統迭代。

## 未解問題

- 購物車要做到哪裡？→ 目前假設：只做「加入購物車」與版頭的數量徽章（REQ-002），不做購物車頁與結帳。

## 目前的假設

選 A；範圍 = 搜尋（P0）→ 商品頁（P0）→ 首頁（P1）。
