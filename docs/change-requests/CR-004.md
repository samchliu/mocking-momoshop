# CR-004：BR-003 釐清數量修正方式（R2）與購物車儲存格式（R6）

> **不要試圖阻止變更。讓變更的成本與影響清楚可見。**

## 要求的變更（Requested Change）

起草 REQ-006／BR-004（購物車頁）時，歧義檢查指出 BR-003 有兩處會被引用、但文字不夠精確。PM 決定修正（REQ-006 D13，2026-11-20）。

**變更 1：** BR-003#R2

> 數量必須是整數，範圍為 1 到 min(該規格庫存, 每人限購數)；超出範圍的輸入修正到最近的合法值

改為：

> 數量必須是整數，範圍為 1 到 min(該規格庫存, 每人限購數)。修正方式：輸入不是有限數字（含空白）時視為 1；非整數無條件捨去；結果再限制在 1 到上限之間

原因：原文「最近的合法值」與 BR-003 範例 E2「1.7 → 1」矛盾（1.7 最近的整數是 2）。新文字與 E2 一致，不改變 E1、E2 的預期結果。

**變更 2：** BR-003#R6

> 購物車數量 = 各品項數量總和；存在瀏覽器（localStorage），讀回時驗證格式，格式不符則視為空購物車

改為：

> 購物車數量 = 各品項數量總和；存在瀏覽器（localStorage），讀回時驗證格式，格式不符則視為空購物車。格式不符包含：不是物件、`lines` 不是陣列、任一列的 `productId` 不是字串、`variantId` 不是字串或 null、`quantity` 不是 ≥ 1 的整數，或兩列的 (`productId`, `variantId`) 相同

並在 BR-003「範例」新增：

| #   | 情境                                                | 預期結果     | 規則 |
| --- | --------------------------------------------------- | ------------ | ---- |
| E7  | localStorage 中一列 `quantity` 為 0 或 1.5          | 購物車視為空 | R6   |
| E8  | localStorage 中兩列 (`productId`, `variantId`) 相同 | 購物車視為空 | R6   |

原因：原文沒有定義「格式」，購物車頁（BR-004）需要依賴「儲存數量為 ≥ 1 的整數且品項不重複」。

## 原因（Reason）

REQ-006、BR-004 的金額與結帳品項數都依賴這兩條；不釐清時，實作者會在四捨五入／捨去、重複列合併／保留之間各自猜測。
