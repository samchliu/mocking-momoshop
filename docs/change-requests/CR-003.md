# CR-003：REQ-004 移除「不做固定版頭」，改由 REQ-005 規定固定與收合

> **不要試圖阻止變更。讓變更的成本與影響清楚可見。**

## 要求的變更（Requested Change）

> 「固定版頭，收合時隱藏分類列」
> —— PM，2026-11-20（合併 REQ-005 時與 REQ-004 衝突的決定）

**變更 1：** REQ-004「不在範圍內」一節的這一條：

> 捲動時固定版頭（sticky）：版頭隨頁面捲動。

改為：

> 捲動時的固定與收合行為由 REQ-005 規定（版頭固定在視窗頂端；捲動後只留第一列、隱藏分類導覽）。

**變更 2：** REQ-004#AC4 的「保留瀏覽器原生捲軸，不加漸層、箭頭等額外提示」改為：

> 不顯示水平捲軸（仍可用觸控、觸控板、Shift＋滾輪與 Tab 聚焦水平捲動），不加漸層、箭頭等額外提示。

原因：REQ-005 固定分類導覽高 45px（版頭展開版 109px）。在捲軸會占空間的平台（例如 Windows 桌機），44px 連結加上捲軸會超過 45px（REQ-005 Q31）。

REQ-004 的其他內容（容器、底色、兩列結構、分類導覽的內容、AC1–AC3、AC5，以及 AC4 的單列不換行、44px 點擊區、Tab 聚焦捲入）不變。

## 原因（Reason）

PM 要求復刻實站的固定版頭與捲動收合（EXP-002 O1、O2、O4）。REQ-004 核准時把固定版頭列為不做，兩份核准文件互相矛盾，需由本 CR 解除。

**風險／副作用：**

- 收合時分類導覽不可見；捲動後要切換分類，需回到頂端。這與實站一致（EXP-002 O4）。
- REQ-004#AC4 的分類導覽 e2e 若在捲動後量測會失敗，需在頂端量測。
- 隱藏捲軸後，只有滑鼠滾輪、沒有觸控板的桌機使用者較難發現分類導覽可以水平捲動（需 Shift＋滾輪或 Tab）。
