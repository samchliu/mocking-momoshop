# CR-002：API-001 新增首頁商品流端點 GET /api/home/feed

> **不要試圖阻止變更。讓變更的成本與影響清楚可見。**

## 要求的變更（Requested Change）

> 「API：新增 `GET /api/home/feed?page=`」——同意
> —— PM，2026-11-20（REQ-005 Q3）

REQ-005「限制」一節列出 CR 須定義的項目：回應格式（含 `total`）、`page` 非法或越界的行為、跨批次 `id` 不重複、錯誤與重試、逾時秒數（Q27）、回應 `page` 與請求一致。

## 提議的 API-001 變更內容

### 端點

| Method | Path                   | 用途                              |
| ------ | ---------------------- | --------------------------------- |
| GET    | `/api/home/feed?page=` | 首頁「推薦商品」商品流（REQ-005） |

### 請求

- `page`：正整數，1 起算。

### 回應

```ts
interface HomeFeedResponse {
  items: ProductSummary[] // 長度 = pageSize；最後一批可少於 pageSize；totalPages 為 0 時為 []
  page: number // 等於請求的 page
  pageSize: number // 20
  totalPages: number // mock 固定為 5
  total: number // 所有批的商品總數；mock 固定為 100
}
```

| 規則 | 內容                                                                                                                                    |
| ---- | --------------------------------------------------------------------------------------------------------------------------------------- |
| F1   | `page` 缺少、非正整數（0、負數、小數、非數字）時回 **400**；不像 BR-002#R5 那樣修正，因為商品流只由前端程式依序請求，非法值代表前端錯誤 |
| F2   | `page > totalPages` 時回 **200**，`items: []`，`page` 照請求值回傳；前端以 `page >= totalPages` 判斷到底，正常流程不會請求到這裡        |
| F3   | 同一次 mock 資料內，所有批的 `items[].id` 互不重複；同一 `page` 重複請求回傳相同內容（排序穩定）                                        |
| F4   | 價格欄位同 `ProductSummary`，不含 `flashPrice`（REQ-005 AC12）                                                                          |

### 錯誤

沿用 API-001 既有錯誤表：400 不重試；5xx 查詢自動重試 2 次。逾時沿用 `api/request` 預設 **8 秒**（`src/api/client.ts` 的 `DEFAULT_TIMEOUT`），逾時與網路錯誤視為失敗（REQ-005 AC6）。

### 效能預期

沿用 API-001：預設延遲 300ms，可用 `?latency`、`?fail` 故障注入。

## 原因（Reason）

REQ-005（已核准）需要可分頁的首頁商品流；API-001 的 `GET /api/home` 只回傳固定的商品帶，沒有分頁。

## 影響（Impact）

| 領域                      | 影響程度 | 說明                                                                        | 受影響的知識 / 程式碼                                 |
| ------------------------- | -------- | --------------------------------------------------------------------------- | ----------------------------------------------------- |
| 產品影響（Product）       | 低       | 只新增端點；既有頁面行為不變                                                | REQ-005                                               |
| 前端影響（Frontend）      | 中       | 新增 `parseHomeFeedResponse` parser 與 `useHomeFeedQuery`（infinite query） | `src/features/home`、`src/features/catalog`（parser） |
| 後端影響（Backend）       | 中       | mock handler 新增路由；mock 商品目前只有 70 個，不足 100 個（見未解問題）   | `src/api/mock/handlers.ts`、`src/api/mock/data.ts`    |
| AI / Agent 影響           | 無       | —                                                                           | —                                                     |
| 資料影響（Data）          | 中       | mock 商品擴充到 ≥ 100 個，搜尋結果數、品牌件數會跟著改變                    | `src/api/mock/data.ts`、搜尋相關測試                  |
| 測試影響（Testing）       | 中       | 新增 handler 單元測試（F1–F3）；檢查依賴商品數的既有測試                    | `src/api/mock/*.test.ts`                              |
| 文件影響（Documentation） | 低       | API-001 端點表、回應型別、變更歷史                                          | API-001                                               |

**風險／副作用：**

- 擴充 mock 商品會改變搜尋頁的結果數與 facet 件數，可能讓 e2e 或依賴固定數量的測試失敗。

**未解問題：**

| #   | 問題                                           | 決定                                                  |
| --- | ---------------------------------------------- | ----------------------------------------------------- |
| Q1  | mock 只有 70 個商品，湊不到 100 個不重複的商品 | 資料產生器擴充到 ≥ 100 個，商品流與搜尋共用同一份資料 |
