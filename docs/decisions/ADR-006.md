# ADR-006：共用基礎 UI 元件

> **每個重要的技術決策都應該有可追溯的理由。**
> 一旦被接受，本 ADR 不會被改寫。要改變決策，請寫一份新的 ADR 來取代它。可以在最下方追加備註。

**決策者：** RD
**決策日期：** （待核准）

## 背景（Context）

ARCH-001 的 `components/` 目前只收「基礎設施型」元件（SmartImage、SafeLink、LazySection、StatusView、Spinner、Dialog、Toast、ErrorBoundary、OfflineBanner）。按鈕與輸入框這類最基本的互動元件**沒有共用實作**，各 feature 以自己的 CSS module 重寫（2026-11-20 盤點）：

| 種類   | 現有實作                                                                                                                                                                   |
| ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 按鈕   | `SearchBox .button`、`SearchResults .secondaryButton／.linkButton／.sortButton`、`Goods .stepButton／.addButton`、`StatusView .button`、`RouteErrorPage` 無樣式 `<button>` |
| 輸入框 | `SearchBox .input`、`SearchResults.module.css .input`（`FilterPanel` 的價格區間）、`Goods .qtyInput`                                                                       |
| Chip   | `HotKeywords .chip`（白底、框線、膠囊圓角）、`SearchResults .chip`（灰底、無框、`--radius-md`）                                                                            |

已觀察到的問題：

1. **同一件事寫兩次**：`SearchResults .secondaryButton` 與 `StatusView .button` 只差 padding（`--space-4` 對 `--space-6`）。
2. **狀態樣式不一致**：disabled 有的用 `opacity: 0.5`（StatusView），有的換成灰底灰字（`.addButton`），有的只換字色（`.stepButton`）；`cursor: pointer` 有的有、有的沒有。
3. **跨切面規則要改多處**：觸控目標 ≥ 44px 的 `min-height: 44px` 在 CSS 中出現 18 次；移除文字輸入框 focus outline 時必須同時改 `global.css` 與 `SearchBox.module.css`。
4. **規則無法被檢查**：CLAUDE.md 的「觸控目標 ≥ 44px」與「會改變資料的操作 pending 時停用按鈕」（加入購物車的部分即 BR-003#R4）目前只能靠 review 逐一確認，沒有單一實作可以測試。

## 決策（Decision）

我們將在 `src/components/` 新增 `Button` 與 `TextInput` 兩個無業務的基礎元件，以 CSS module + `var(--token)` 實作、**不引入新的 runtime 依賴**，並依下方「遷移清單」把既有寫法換成它們。**自「遷移順序」第 1 步合併到 main 起，新寫的按鈕與文字輸入框必須使用這兩個元件**；在此之前新寫的按鈕與輸入框使用原生元素，並在對應 feature 的遷移步驟中一併遷移。

強制使用的範圍：

- 按鈕：有可見文字的 `<button>`。**純圖示按鈕**（只有圖示、以 `aria-label` 命名，例如 Dialog 關閉鈕、輪播箭頭）使用原生 `<button>`，不適用本 ADR。
- 文字輸入框：`type` 為 `text`、`search`、`number` 的 `<input>`。其他 `type`（`email`、`password`、`tel` 等）與 `<textarea>` 使用原生元素，不適用本 ADR。
- 遷移清單標為「不遷」的種類不適用。

### 範圍

| 元件         | 決定   | 說明                                                                                                                |
| ------------ | ------ | ------------------------------------------------------------------------------------------------------------------- |
| `Button`     | 抽出   | 見「Button 契約」                                                                                                   |
| `TextInput`  | 抽出   | 見「TextInput 契約」                                                                                                |
| Chip         | 不抽   | 兩處視覺不同，是否統一見「待決問題」。Chip 維持現狀，**不改用 `Button`**                                            |
| 數量步進器   | 不抽   | 只有 `PurchasePanel` 一處使用，`.stepButton`、`.qtyInput` 留在 `features/goods`，不改用新元件                       |
| 排序切換按鈕 | 不抽   | `SortBar` 是 `aria-pressed` 的分段控制，選中樣式屬於搜尋領域；`.sortButton` 留在 `features/search`，不改用 `Button` |
| 連結         | 不涵蓋 | `Button` 只渲染 `<button>`，不支援 `as="a"`；導覽一律用 `<SafeLink>`，即使外觀像按鈕也不在本 ADR 範圍               |

### Button 契約

**檔案**：`src/components/Button/Button.tsx`、`Button.module.css`、`Button.test.tsx`；由 `src/components/index.ts` 匯出 `Button`。

**Props**

| Prop        | 型別                                             | 預設        | 說明                                                                                                                                                                                           |
| ----------- | ------------------------------------------------ | ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `variant`   | `'primary' \| 'secondary' \| 'text'`             | `'primary'` |                                                                                                                                                                                                |
| `tone`      | `'brand' \| 'cart' \| 'nav'`                     | `'brand'`   | **只有 `variant` 為 `'primary'` 或省略時可傳**（省略即 primary，`<Button tone="cart">` 合法）；`variant` 為 `'secondary'`／`'text'` 時傳 `tone` 必須編譯失敗（TypeScript discriminated union） |
| `size`      | `'md' \| 'lg'`                                   | `'md'`      | `lg` 只用於頁面主要 CTA（放入購物車）                                                                                                                                                          |
| `pending`   | `boolean`                                        | `false`     | 見「狀態」                                                                                                                                                                                     |
| `fullWidth` | `boolean`                                        | `false`     | `width: 100%`，所有斷點                                                                                                                                                                        |
| `type`      | `'button' \| 'submit' \| 'reset'`                | `'button'`  | 表單送出時由呼叫端傳 `'submit'`                                                                                                                                                                |
| `className` | `string`                                         | —           | **僅用於排版**，見「className 覆寫規則」                                                                                                                                                       |
| `ref`       | `Ref<HTMLButtonElement>`                         | —           | React 19 的 ref prop                                                                                                                                                                           |
| 其餘        | `ButtonHTMLAttributes` 去掉 `style`、`aria-busy` | —           | 不接受 `style`（避免任意顏色與尺寸）；不接受 `aria-busy`（只由 `pending` 決定）                                                                                                                |

**className 覆寫規則**

- 可由呼叫端 className 覆寫的屬性：`width`、`min-width`、`max-width`、`margin`（含各方向）、`flex`、`flex-grow`、`flex-shrink`、`flex-basis`、`align-self`、`justify-self`、`order`。
- 元件以 `:where(.root)`（權重 0）宣告上列屬性的預設值，因此任何呼叫端 class 都會蓋過，與 CSS 載入順序無關。
- 其他屬性（顏色、框線、圓角、padding、高度、字級、字重）以一般 class 宣告；呼叫端不得在 className 中設定，由 review 檢查。

**variant × tone 對照（共 5 種合法組合）**

| variant     | tone    | 背景            | 文字                     | 框線                | hover                    |
| ----------- | ------- | --------------- | ------------------------ | ------------------- | ------------------------ |
| `primary`   | `brand` | `--color-brand` | `--color-brand-contrast` | 無                  | 無變化                   |
| `primary`   | `cart`  | `--color-cart`  | `--color-brand-contrast` | 無                  | 無變化                   |
| `primary`   | `nav`   | `--color-nav`   | `--color-brand-contrast` | 無                  | 無變化                   |
| `secondary` | —       | `--color-bg`    | `--color-brand`          | 1px `--color-brand` | 背景 `--color-bg-subtle` |
| `text`      | —       | 無              | `--color-brand`          | 無                  | 無變化；底線常駐         |

**尺寸**

| size | min-height | min-width | padding-inline             | 字級                                                 |
| ---- | ---------- | --------- | -------------------------- | ---------------------------------------------------- |
| `md` | 44px       | 44px      | `--space-4`（`text` 為 0） | `primary`：`--fs-md`；`secondary`／`text`：`--fs-sm` |
| `lg` | 48px       | 44px      | `--space-4`（`text` 為 0） | `--fs-lg`                                            |

- 字重：`primary` 600；`secondary`、`text` 400（不隨 size 改變）。
- 圓角：`primary`、`secondary` 為 `--radius-sm`；`text` 無。
- 版面：`display: inline-flex`、`align-items: center`、`justify-content: center`、`white-space: nowrap`；預設寬度由內容決定（`fullWidth` 時 `width: 100%`）。
- `:active` 不設樣式。
- 44px 以 `<button>` 元素本身的框計算，不用 padding 或偽元素擴大點擊區。`text` 也遵守 44px，因此**不用於段落內的行內文字**；行內需要可點擊文字時用 `<SafeLink>`。
- focus：沿用 `global.css` 的 `:focus-visible` outline，元件不另設。
- `cursor`：可點時 `pointer`；disabled 時 `not-allowed`；pending 時 `progress`。

**狀態**

| 狀態       | DOM                                       | 視覺                                                                                                                                                                                                      |
| ---------- | ----------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 一般       | 無 `disabled`，**不輸出** `aria-busy`     | 依上表                                                                                                                                                                                                    |
| `disabled` | 原生 `disabled` 屬性                      | `primary`：背景 `--color-border`、文字 `--color-text-muted`，**不加框線**；`secondary`：背景與框線 `--color-border`、文字 `--color-text-muted`；`text`：文字 `--color-text-muted`，底線保留；hover 無變化 |
| `pending`  | 原生 `disabled` 屬性 + `aria-busy="true"` | 與 `disabled` 相同，僅 `cursor: progress`；**不顯示 Spinner、不改文字**（需要改文字由呼叫端改 children）                                                                                                  |

- 原生 `disabled` 的實際值為 `disabled || pending`：`pending` 為 true 時，即使呼叫端傳 `disabled={false}` 仍為停用。`aria-busy` 只在 `pending` 為 true 時輸出 `"true"`。
- 使用原生 `disabled`：pending／disabled 時按鈕離開 Tab 順序，滑鼠與鍵盤都不會觸發 `onClick`。
- **`pending` 只表示「此按鈕觸發的請求進行中」**。其他停用原因（售完、數量不合法、表單未填等）一律傳 `disabled`，不得放進 `pending`。
- **焦點還原（呼叫端負責）**：按鈕進入 pending 時若持有焦點，原生 `disabled` 會讓焦點遺失。呼叫端以 `ref` 記錄「進入 pending 時按鈕是否為 `document.activeElement`」；`pending` 由 true 轉為 false 時，若當時持有焦點、按鈕仍在 DOM 中、且按鈕未被 `disabled`，呼叫 `focus()` 還原。按鈕已卸載（例如重試成功後錯誤畫面消失）或轉為 disabled（例如加入後售完）時不還原。
- **責任歸屬**：`Button` 只負責「pending 時停用」。BR-003#R4「同一時間對同一商品只能有一個加入請求」的保證仍由呼叫端（`useAddToCart`）負責，`Button` 不做去重。

### TextInput 契約

**檔案**：`src/components/TextInput/TextInput.tsx`、`TextInput.module.css`、`TextInput.test.tsx`；由 `src/components/index.ts` 匯出 `TextInput`。

**Props**

| Prop         | 型別                               | 預設      | 說明                                                               |
| ------------ | ---------------------------------- | --------- | ------------------------------------------------------------------ |
| `type`       | `'text' \| 'search' \| 'number'`   | `'text'`  | 其他 type（checkbox、radio 等）不在範圍                            |
| `appearance` | `'boxed' \| 'bare'`                | `'boxed'` | `bare`：用於自己畫外框的複合控制項（例：SearchBox 的膠囊外框）     |
| `className`  | `string`                           | —         | 僅用於排版，覆寫規則同 Button（以 `:where(.root)` 宣告可覆寫屬性） |
| `ref`        | `Ref<HTMLInputElement>`            | —         |                                                                    |
| 其餘         | `InputHTMLAttributes` 去掉 `style` | —         | label 關聯（`<label htmlFor>` 或 `aria-label`）由呼叫端負責        |

**樣式**

| 項目           | `boxed`                                                                        | `bare`                                                       |
| -------------- | ------------------------------------------------------------------------------ | ------------------------------------------------------------ |
| 寬度           | `width: 100%`                                                                  | `width: 100%`                                                |
| min-height     | 44px                                                                           | 44px                                                         |
| padding-inline | `--space-2`                                                                    | `--space-3`                                                  |
| 框線           | 1px `--color-border`                                                           | 無                                                           |
| 圓角           | `--radius-sm`                                                                  | 無                                                           |
| 背景           | `--color-bg`                                                                   | 透明                                                         |
| 字級           | `--fs-lg`（16px），所有斷點，避免 iOS 縮放                                     | 同左                                                         |
| focus          | `outline: none`；框線顏色改為 `--color-focus`，粗細維持 1px                    | `outline: none`；focus 提示由外層容器以 `:focus-within` 負責 |
| disabled       | 背景 `--color-bg-subtle`、文字 `--color-text-muted`，框線維持 `--color-border` | 文字 `--color-text-muted`                                    |

- 上表未列出的狀態（hover、`:active` 等）不設樣式。

- `type="number"` 的原生上下箭頭維持瀏覽器預設，不隱藏。
- 不定義 `aria-invalid` 的錯誤樣式：目前沒有使用處，出現時另行決定。
- `global.css` 中針對文字輸入框移除 outline 的覆寫**保留不動**（未遷移的 `.qtyInput` 仍依賴它）；`TextInput` 自身也設 `outline: none`。

### 測試

`Button.test.tsx`（以 `getByRole('button')` 查詢）：

- 未傳 `type` 時 `type="button"`；傳 `type="submit"` 時為 `submit`。
- 按鈕取得焦點後，點擊、Enter、Space 各觸發 `onClick` 1 次。
- `pending` 時：按鈕為 `disabled`、`aria-busy="true"`。
- `pending` 時不觸發：先 render 一般狀態並 `focus()` 按鈕，再以 `rerender` 設 `pending`，接著以 `userEvent` 執行點擊、Enter、Space，`onClick` 呼叫次數為 0。
- `pending` 且傳 `disabled={false}` 時仍為 `disabled`。
- 非 `pending` 時不存在 `aria-busy` 屬性。
- `disabled` 時點擊不觸發 `onClick`。
- 型別：`<Button variant="secondary" tone="cart" />` 與 `<Button variant="text" tone="nav" />` 以 `// @ts-expect-error` 標注，`npm run typecheck` 必須通過（代表確實編譯失敗）；`<Button tone="cart" />` 不加標注且必須通過。

焦點還原（在各呼叫端的測試中驗證）：

- `PurchasePanel`：以鍵盤（focus 後按 Enter）加入購物車，請求成功後焦點回到「放入購物車」按鈕；加入後售完時不還原。
- `StatusView`：以鍵盤觸發重試且重試失敗時，焦點回到「重試」按鈕。

`TextInput.test.tsx`（以 `getByLabelText` 查詢）：

- 與 `<label>` 關聯後可被查到；輸入文字觸發 `onChange`。
- `type="number"` 時 role 為 `spinbutton`。
- `disabled` 時無法輸入。

尺寸（44px／48px、SearchBox 送出鈕 64px）、顏色與 focus 樣式在 jsdom 中無法量測，不寫單元測試；由 RD 在每一步合併時人工檢查（見「後果」）。

## 替代方案（Alternatives）

| 方案                                         | 摘要                                         | 為什麼沒選                                                                                              |
| -------------------------------------------- | -------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| A（採用）React 元件 + CSS module             | `Button`／`TextInput` 放在 `src/components/` | —                                                                                                       |
| B 全域工具 class（`.btn`、`.btn--primary`）  | 寫在 `global.css`，各處加 className          | 無法封裝行為（`type="button"`、`pending` → `aria-busy`），規則仍需靠 review；全域 class 命名衝突風險    |
| C 引入 UI 套件（Radix、MUI、Headless UI 等） | 用第三方元件                                 | 違反「不新增 runtime 依賴」；需求只有兩個簡單元件，套件的 bundle 與樣式覆寫成本不成比例；仍需自己做視覺 |
| D 維持現狀                                   | 各 feature 自寫                              | 背景所列 4 個問題持續存在，且每個新 feature（ARCH-001 擴展性所列的 `/discover`、`/live`）會再複製一份   |
| E 一次抽出全部（含 Chip、步進器、SortBar）   | 把所有重複都收進 `components/`               | Chip 尚未有統一的設計結論；步進器只有一處使用，提早抽象會綁死介面                                       |

## 後果（Consequences）

**正面**

- 觸控目標、disabled／pending、focus 等跨切面規則集中在一處，行為面可單元測試。
- 新 feature 不必再寫按鈕與輸入框樣式。
- 各 feature 的 CSS module 縮小，只留領域排版。

**負面**

- `src/components/` 歸整合者所有：feature 遷移必須等第 1 步合併後才能開始。
- 遷移期間新舊寫法並存。
- 以下視覺會改變，屬於預期變動：
  - `StatusView` 按鈕的 padding 由 `--space-6` 變為 `--space-4`。
  - `StatusView` 按鈕的 disabled 由 `opacity: 0.5` 改為灰底灰字。
  - SearchBox 送出按鈕多了 `--radius-sm` 圓角（被膠囊外框裁切，實際幾乎不可見）。
  - SearchBox 輸入框 focus 時，膠囊外框改為 `--color-focus`。
  - 價格區間輸入框 focus 時框線改為 `--color-focus`。
- 目前沒有啟用中的截圖比對測試（`e2e/smoke.spec.ts` 中的 `toHaveScreenshot` 已註解），視覺回歸只能人工檢查：**每一步合併前，由 RD 在 1280px 與 375px 兩種寬度檢查受影響頁面（首頁、搜尋結果、商品頁、錯誤頁），確認只有上列預期變動，且 SearchBox 送出鈕寬度為 64px。**
- 檢查時出現上列以外的視覺變動：**退回該 worktree 修正**。只有 RD 確認該變動屬於預期時，才在合併前以本 ADR 的「備註」追加記錄後合併。

**需要的後續行動**

- 更新 ARCH-001 的元件表與 `components/` 說明（另開 draft，由 RD 核准）。
- 更新 CLAUDE.md 的 Coding rules：「有文字的按鈕用 `<Button>`、text／search／number 輸入框用 `<TextInput>`（純圖示按鈕、其他 input type、textarea 與遷移清單標為『不遷』的種類除外）」。
- 依「遷移順序」開 4 個 worktree。

## 取捨（Trade-offs）

| 我們得到                           | 我們放棄                                           |
| ---------------------------------- | -------------------------------------------------- |
| 一致的互動狀態與可測試的跨切面規則 | 各 feature 自由調整按鈕外觀的彈性                  |
| 零新依賴、與既有 token 系統一致    | 現成套件的完整 a11y 行為（目前只需要原生元素即可） |
| 介面小、只抽有 ≥ 2 處使用的元件    | Chip、步進器、SortBar 的重複暫時保留               |

**重新檢視條件：**

- 出現原生元素無法滿足的複合元件需求（combobox、menu、tabs 等需要完整 ARIA 模式）時，重新評估方案 C。
- Chip 的設計統一有結論，或步進器出現第二個使用處時，追加抽出。
- 需要在上表 5 種 variant × tone 組合之外**新增任何組合或新的 size** 時，先確認是否在承接不該共用的領域樣式，並以新 ADR 記錄。
