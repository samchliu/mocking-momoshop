# ADR-002：狀態分層

## 背景（Context）

REQ-001 要求快速切換條件時畫面對應最新條件、URL 可分享；REQ-002 要求加入購物車可樂觀更新並回滾。不同來源的狀態若混在一個 store，容易出現競態與重複資料。

## 決策（Decision）

依狀態的「來源」決定放在哪裡：

| 狀態              | 例子                     | 放在                                                        |
| ----------------- | ------------------------ | ----------------------------------------------------------- |
| Server state      | 搜尋結果、商品           | TanStack Query（快取、去重、取消、重試）                    |
| URL state         | 關鍵字、排序、篩選、頁碼 | URL（`useSearchParamsState` + `features/search/params.ts`） |
| 跨頁 client state | 購物車                   | Context + `useReducer`（純函式），localStorage 持久化       |
| 元件狀態          | 選中的規格、數量輸入     | `useState`                                                  |

## 替代方案（Alternatives）

| 方案                               | 不選的原因                                                     |
| ---------------------------------- | -------------------------------------------------------------- |
| Redux Toolkit / Zustand 全域 store | 規模不需要；server state 放進 store 等於自己重寫快取與競態處理 |
| useEffect + fetch                  | 競態、重複請求、快取都要自己寫，是 AI 最常產出錯誤的地方       |
| 篩選條件放 component state         | 無法分享、重新整理就遺失                                       |

## 後果（Consequences）

- 引入 TanStack Query（約 13KB gzip），是唯一為資料流新增的套件。
- 「舊回應覆蓋新條件」由 query key + AbortSignal 結構性地避免，而不是靠每個元件記得處理。

## 取捨（Trade-offs）

多一個依賴與一套概念，換取競態安全與快取。
