# ADR-001：渲染策略 — Vite CSR SPA

## 背景（Context）

- 實作時間約 120 分鐘，評分重視架構與取捨，不重視 SEO 或正式部署（REF-001）。
- 實站以客戶端渲染載入商品內容（REF-002：HTTP 抓取只得到 HTML 殼）。
- 資料全部是 mock，沒有後端可以做伺服器端渲染的資料來源。

## 決策（Decision）

使用 Vite + React 的 CSR SPA，以 route-level code splitting 與首屏以下延遲載入控制首屏成本。

## 替代方案（Alternatives）

| 方案               | 優點                            | 不選的原因                                          |
| ------------------ | ------------------------------- | --------------------------------------------------- |
| Next.js（SSR/ISR） | 商品頁 SEO、首屏 HTML、CDN 快取 | mock 資料下收益無法展示；部署與心智成本吃掉有限時間 |
| Astro + islands    | 首屏極小                        | 搜尋頁高互動，islands 間狀態共享成本高              |

## 後果（Consequences）

- 首屏需要等 JS；以小 bundle 與 lazy route 補償，並以 Lighthouse 量測（OPS-001）。
- 搜尋結果與商品頁對爬蟲不友善 → 列為已知限制。

## 取捨（Trade-offs）

用 SEO 與首屏 HTML，換取交付速度與實作的單純度。

**演進方向**：正式環境中，流量最大、SEO 最重要的商品頁應改為 SSR/ISR + CDN 快取；搜尋頁可維持 CSR（個人化、高互動）。由於資料存取集中在 `api/` 與 query hooks，遷移時 feature 元件可以重用。
