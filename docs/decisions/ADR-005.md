# ADR-005：URL 設計

## 背景（Context）

實站搜尋為 `/search/searchShop.jsp?keyword=` 並轉址為 `/search/<keyword>`；商品為 `/goods/GoodsDetail.jsp?i_code=` 並轉址為 `/product/<id>`（REF-002）。題目建議的路由為 `/search/...`、`/goods/...`（REF-001）。

## 決策（Decision）

| 路由                                                   | 說明                                                              |
| ------------------------------------------------------ | ----------------------------------------------------------------- |
| `/`                                                    | 首頁                                                              |
| `/search/:keyword?sort=&brand=&brand=&min=&max=&page=` | 關鍵字在 path（與實站轉址後一致），條件在 query；預設值不寫進 URL |
| `/goods/:id`                                           | 商品頁（依題目建議，不用實站的 `/product`）                       |
| `/goods/GoodsDetail.jsp?i_code=:id`                    | 舊網址相容，導向 `/goods/:id`                                     |
| `*`                                                    | 404                                                               |

## 替代方案（Alternatives）

| 方案                        | 不選的原因               |
| --------------------------- | ------------------------ |
| `/search?keyword=`          | 與實站轉址後的形式不一致 |
| 條件序列化成單一 `?q=` JSON | 不可讀、不利分享與除錯   |

## 後果（Consequences）

- URL 是搜尋條件的唯一來源；`params.ts` 負責正規化，非法值被修正（BR-002#R5）。

## 取捨（Trade-offs）

保留實站的 path 風格，以多一層 legacy redirect 為代價換取相容性。

## 備註（只能追加）

- 2026-11-20（RPT-001 規格缺口）：URL 中不合法的條件不改寫網址，只在解讀時退回預設：`sort` 非法視為「綜合推薦」，`min`／`max` 非法時忽略該條件（REQ-001#AC9）。唯一會被改寫的是 `page`（BR-002#R5、REQ-001#AC4），因為頁碼錯誤會讓使用者看到與網址不符的頁面；其他條件退回預設後畫面與網址語意一致，改寫只會增加一次歷史紀錄替換而沒有收益。（AI 起草，待 RD 確認）
- 2026-11-20（補充前一則）：「後果」中「非法值被修正」指**解讀時**退回預設；寫回網址的只有 `page`，依據是 REQ-001#AC4（BR-002#R5 只規定頁碼如何解讀）。`page` 的改寫使用 history replace，修正為 1 時移除參數，其他參數原樣保留。使用者變更條件時只改寫該條件的參數（REQ-001#AC9）。解讀細則（大小寫、重複參數、`brand`）見 REQ-001#AC9。（AI 起草，待 RD 確認）
