# ADR-003：Mock 後端

## 背景（Context）

題目要求純前端、不呼叫真實網站 API（REF-001）。但前端工程判斷（錯誤處理、競態、重試）必須在「像真的網路」的條件下才能被驗證與展示。

## 決策（Decision）

- 在 repo 內實作 mock backend（`src/api/mock/`），透過 `request()` 的 transport 呼叫，對前端而言與真實 HTTP 相同（Response 物件、狀態碼、JSON）。
- 資料由**固定種子的產生器**建立（同樣的種子永遠產生同樣的商品），測試與 e2e 可重現。
- 業務規則（BR-002 搜尋、BR-003 的 409）在 mock 後端執行，前端不重複實作。
- 故障注入：`?latency=ms`、`?fail=0~1`、`?offline=1`。

## 替代方案（Alternatives）

| 方案                  | 不選的原因                                                                                  |
| --------------------- | ------------------------------------------------------------------------------------------- |
| MSW（Service Worker） | 業界標準、Network 面板看得到；但 SW 在 preview／Lighthouse 環境需額外處理，故障注入要另外寫 |
| json-server           | 需要另一個程序；無法表達 BR-002 的搜尋規則                                                  |
| 靜態 JSON import      | 無法展示 loading、錯誤、競態                                                                |

## 後果（Consequences）

- 改接真實 API 時只需把 transport 換成 `fetch`，parser 保留為契約檢查。
- mock 後端的規則實作本身需要測試（BR-002 的單元測試寫在這一層）。

## 取捨（Trade-offs）

放棄 Network 面板的可見性（以 telemetry 補足，見 OPS-001），換取零設定、可重現與內建故障注入。
