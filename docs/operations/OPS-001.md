# OPS-001：驗證與可觀測性

## 驗證：五層閘門（由快到慢）

| 層      | 指令                                | 抓什麼                                                                             | 何時跑              |
| ------- | ----------------------------------- | ---------------------------------------------------------------------------------- | ------------------- |
| 1. 知識 | `npx kb validate --code-root .`     | 知識斷鏈、權威外洩、程式碼引用不存在或已棄用的知識 ID、`implemented_in` 路徑不存在 | 每次 commit 前      |
| 2. 靜態 | `npm run typecheck && npm run lint` | 型別、React hooks 規則、a11y、XSS sink                                             | 每次 commit 前      |
| 3. 追溯 | `npm run spec:check`                | 每條 `REQ-xxx#ACn`、`BR-xxx#Rn` 是否都有測試；測試是否引用不存在的條件             | 每次 commit 前      |
| 4. 行為 | `npm test`、`npm run e2e`           | 規則與元件行為；關鍵流程（含故障注入）                                             | 每個 feature 完成時 |
| 5. 品質 | `npm run lhci`                      | Performance／A11y／Best Practices 門檻、LCP、CLS                                   | 整合後              |

1～4 合併為 `npm run verify`（e2e 與 lhci 另外跑），作為 agent 任務的完成定義（ADR-004）。

## 可觀測性：執行期

`lib/telemetry` 提供單一事件匯流排，沒有外部依賴：

| 事件     | 來源                                      | 欄位                                       |
| -------- | ----------------------------------------- | ------------------------------------------ |
| `api`    | `api/request()`                           | path、status、durationMs、errorKind、retry |
| `error`  | ErrorBoundary、route errorElement         | name、message、component                   |
| `vital`  | PerformanceObserver（LCP、CLS、INP 近似） | name、value                                |
| `action` | 加入購物車等關鍵操作                      | name、outcome                              |

- **Sink**：開發環境輸出到 console；`?debug=1` 顯示浮動 debug 面板（最近事件、API 延遲與錯誤率）。正式環境的 sink（例如 sendBeacon 到收集端點、Sentry）為規劃項目，介面已預留。
- **故障注入**：`?latency=3000`、`?fail=0.3`、`?offline=1`，搭配 debug 面板即可在 demo 中觀察重試、錯誤率與回滾。

## 上線前需要補上（規劃中）

1. 收集端點與取樣率；PII 遮罩（關鍵字可能含個資）。
2. 告警：API 錯誤率、LCP p75 劣化。
3. Release 標記（事件附上版本），以便比較版本間的指標。
