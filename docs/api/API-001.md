# API-001：Mock API 合約

## 端點

| Method | Path                                          | 用途                                      |
| ------ | --------------------------------------------- | ----------------------------------------- |
| GET    | `/api/search?q=&sort=&brand=&min=&max=&page=` | 搜尋（BR-002）                            |
| GET    | `/api/products/:id`                           | 商品詳情                                  |
| POST   | `/api/cart/items`                             | 加入購物車（BR-003）                      |
| GET    | `/api/home`                                   | 首頁內容（輪播、限時搶購、商品帶、熱搜）  |
| GET    | `/api/home/feed?page=`                        | 首頁「推薦商品」商品流（REQ-005，CR-002） |

## 目的

定義前端與（mock）後端之間的唯一契約。前端以 parser 驗證每個回應；mock 後端執行 BR-002、BR-003。

## 請求（Request）

- `GET /api/search`：`q` 已依 BR-002#R1 正規化；`brand` 可重複；`min`／`max` 為整數；`page` ≥ 1。
- `GET /api/home/feed`：`page` 為正整數，1 起算（規則見「首頁商品流」）。
- `POST /api/cart/items`：`{ productId: string, variantId: string | null, quantity: number, inCart: number }`（`inCart` = 購物車中該選項已有的數量，mock 環境用來檢查 BR-003#R7）。

## 回應（Response）

```ts
type Money = number // 非負整數，TWD（BR-001#R1）

interface ProductSummary {
  id: string
  brand: string
  name: string
  image: { src: string; alt: string; width: number; height: number }
  price: Money
  listPrice?: Money
  priceFrom?: boolean // BR-001#R2, R6
  promoText?: string
  tags: string[]
  salesCount: number
  rating?: number
  reviewCount?: number
  createdAt: string // ISO，供「新上市」
}

interface SearchResponse {
  items: ProductSummary[]
  total: number
  page: number
  pageSize: number
  totalPages: number // page 已依 BR-002#R5 修正
  facets: Array<{
    key: 'brand'
    label: string
    options: Array<{ value: string; label: string; count: number }>
  }> // BR-002#R7
}

interface Variant {
  id: string
  label: string
  price: Money
  listPrice?: Money
  stock: number
}
interface ProductDetail extends ProductSummary {
  category: Array<{ id: string; label: string }> // 麵包屑
  images: ProductSummary['image'][]
  highlights: string[]
  variants: Variant[] // 選項；空陣列 = 無可選選項
  stock: number // 無可選選項時使用；有選項時不使用
  purchaseLimit: number // BR-003#R2
  specs: Array<{ label: string; value: string }> // 規格表（REQ-002#AC11）
}
```

`specs` 規則：

- 必填。沒有規格表時為 `[]`；欄位缺少或為 `null` 時，parser 視為回應格式錯誤（整個商品回應失敗）。
- 每一列的 `label`、`value` 必須是 string 型別（不轉型），以 `String.prototype.trim` 去除頭尾空白後長度 ≥ 1；任何一列不符合時，parser 視為回應格式錯誤。parser 輸出去除頭尾空白後的值；每一列的其他欄位忽略。
- `label`、`value` 由後端保證為純文字；parser 不檢查內容格式，前端一律以文字節點呈現，不保留換行。
- 陣列順序即顯示順序，前端不重新排序。`label` 可重複，依序全部顯示（前端以陣列索引作為 key）。
- 列數與字串長度皆不設上限；前端不截斷文字，過長時自動換行（含長英數字串），不得造成頁面水平捲動。
- 規格表屬於商品層級，不隨所選選項（variant）改變。
- mock 示範資料：`P10001` 有 3 列以上且含一組重複 `label`；`P10002` 的 `specs` 為 `[]`。格式錯誤的情境以 parser 單元測試驗證。

```ts
interface CartAddResponse {
  productId: string
  variantId: string | null
  quantity: number
}

interface HomeResponse {
  banners: Array<{ id: string; image: ProductSummary['image']; href: string }>
  flashSale: {
    startsAt: string
    endsAt: string
    items: Array<ProductSummary & { flashPrice: Money; remaining: number }>
  }
  hotKeywords: string[]
  sections: Array<{ id: string; title: string; items: ProductSummary[] }>
}

interface HomeFeedResponse {
  items: ProductSummary[] // 長度 = pageSize；最後一批可少於 pageSize；越界時為 []
  page: number // 等於請求的 page
  pageSize: number // 20
  totalPages: number // mock 固定為 5
  total: number // 所有批的商品總數；mock 固定為 100
}
```

### 首頁商品流（CR-002）

| 規則 | 內容                                                                                         |
| ---- | -------------------------------------------------------------------------------------------- |
| F1   | `page` 缺少或非正整數（0、負數、小數、非數字）時回 400，不修正（商品流只由前端程式依序請求） |
| F2   | `page > totalPages` 時回 200、`items: []`，`page` 照請求值回傳                               |
| F3   | 所有批的 `items[].id` 互不重複；同一 `page` 重複請求回傳相同內容                             |
| F4   | 商品為 `ProductSummary`，不含 `flashPrice`                                                   |

## 錯誤

| 狀態 | 時機                            | 前端處理                                       |
| ---- | ------------------------------- | ---------------------------------------------- |
| 400  | 參數格式錯誤                    | 不重試，顯示錯誤                               |
| 404  | 商品不存在                      | 顯示找不到商品                                 |
| 409  | 庫存不足或超過限購（BR-003#R7） | 不重試，回滾購物車數量，顯示「超過可購買數量」 |
| 5xx  | 伺服器錯誤（含故障注入）        | 查詢自動重試 2 次；mutation 不重試             |

逾時：`api/request` 預設 8 秒；逾時與網路錯誤在前端視為失敗（REQ-005#AC6）。
| — | HTTP 200 但回應未通過 parser 驗證（含 `specs` 規則） | 不重試，顯示一般錯誤與手動重試（REQ-002#AC6） |

## 執行的商業規則

BR-002（全部）、BR-003#R7。

## 效能預期

- 預設延遲 300ms（可用 `?latency` 調整）；每頁最多 20 筆。
