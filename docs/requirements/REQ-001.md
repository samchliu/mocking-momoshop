# REQ-001：搜尋結果頁

## 問題

使用者知道想買什麼（例：「iphone」），需要快速縮小範圍：依品牌、價格篩選，依銷量或價格排序，並能把結果連結分享給別人或重新整理後不遺失。

## 目標

- 從輸入關鍵字到看到第一頁結果，路徑最短，且每個條件都反映在 URL。
- 快速切換條件時，畫面永遠對應「最新的條件」（不被舊回應覆蓋）。
- 慢速、失敗、無結果時，使用者知道發生什麼事、下一步可以做什麼。

## 使用者

| 使用者             | 需要                                 |
| ------------------ | ------------------------------------ |
| 有明確目標的購物者 | 關鍵字搜尋、篩選、排序、分頁         |
| 分享連結的人       | URL 完整表達條件，打開就是同一個結果 |

## 範圍

### 必須（Must）

- 版頭搜尋框（所有頁面共用）送出關鍵字 → `/search/:keyword`
- 結果數、商品卡列表（BR-001 價格顯示）
- 排序、品牌篩選（含件數）、價格區間、分頁（BR-002）
- loading／error（可重試）／empty 三種狀態

### 應該（Should）

- 熱門關鍵字列（點擊即搜尋）

### 可以（Could）

- 棋盤式／條列式切換

### 不在範圍內（Out of scope）

- 實站的屬性篩選（尺寸、容量、畫素…）與勾選條件（momo速配、超商取貨…）：屬性是「品類相依」的資料模型，mock 成本高、展示價值低。架構上以 `facets` 抽象保留擴充點（API-001）。
- 搜尋建議（autocomplete）、拼字校正、模糊搜尋。
- 無限捲動：實站使用頁碼，保留頁碼以利分享與 SEO。

## 未解問題

- 「綜合推薦」實站的排序依據不公開 → 以「關鍵字相關度，其次總銷量」近似（BR-002#R3），已記錄為刻意差異。
