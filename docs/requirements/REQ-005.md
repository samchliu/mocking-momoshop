# REQ-005：固定版頭與首頁無限商品流

## 問題

使用者往下逛時，版頭（搜尋、購物車）會被捲走，想搜尋或看購物車就得滑回頂端。首頁的商品帶看完就沒了，逛街型購物者沒有「一直往下逛」的入口。

## 目標

- 任何捲動位置都能一步開始搜尋、看到購物車數量。
- 首頁底部可以持續載入推薦商品；捲得很深時仍然流暢，以 AC8 的 DOM 上限作為驗收依據（不另設 FPS 指標）。
- 本需求是**功能示意**：商品流只提供 5 批（共 100 個），足以展示無限載入與虛擬化，不追求真的無限。

## 用語

| 用語         | 定義                                                                                                                                       |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------ |
| 版頭         | 全站頂部、`position: fixed` 的區塊，即 REQ-004 的兩列版頭：第一列 logo、搜尋框、購物車與數量；第二列分類導覽 `<nav aria-label="商品分類">` |
| 展開版       | `scrollY <= 0` 時的版頭：兩列都顯示，高度 109px（第一列 64px ＋ 分類導覽 45px）                                                            |
| 收合版       | `scrollY > 0` 時的版頭：只顯示第一列，分類導覽隱藏（`display: none`，不在無障礙樹中），高度 64px                                           |
| 商品帶       | REQ-003 既有的「大家都在買／新品上市」橫向區塊                                                                                             |
| 推薦商品     | 本需求新增的區塊；標題為 `<h2>推薦商品</h2>`，位於所有商品帶之後                                                                           |
| 商品流       | 「推薦商品」區塊內可無限載入、虛擬化的商品網格                                                                                             |
| 批           | 商品流一次請求取得的商品，等同 API 的一個 `page`；第 1 批 = `page=1`，每批 20 個                                                           |
| 列           | 商品網格的一橫列；桌機 5 張卡、平板／手機 2 張卡                                                                                           |
| 觸發區       | 相對於視窗的 [0, 2 × `window.innerHeight`) 範圍，即整個視窗再往下延伸 1 個視窗高；元素與此範圍有 ≥ 1px 交集即視為在觸發區內                |
| 偵測元素     | 商品流最後一列之後的元素；在觸發區內即請求下一批                                                                                           |
| 列高         | 卡片高度 + 列間距；≥ 1024px 為 380 + 16 = 396px，< 1024px 為 320 + 12 = 332px                                                              |
| 錨定商品     | 版頭下方第一張 `getBoundingClientRect().top` ≥ 版頭當下高度的商品卡                                                                        |
| 首頁生命週期 | 首頁路由從 mount 到 unmount；每次進入首頁（含站內連結、logo）都是新的生命週期，AC11 的返回為例外                                           |

## 使用者

| 使用者       | 需要                                 |
| ------------ | ------------------------------------ |
| 逛街型購物者 | 往下滑持續看到新商品；隨時可搜尋     |
| 目標型購物者 | 在頁面任何位置都能直接輸入關鍵字搜尋 |

## 範圍

### 必須（Must）

- Layout 內所有路由的固定版頭（REQ-004 的兩列版頭；REQ-004 原「不做固定版頭」由 CR-003 移除）
- 版頭兩種版型（展開版／收合版），以 `scrollY` 切換；搜尋框在兩種版型中是同一個 DOM 元素
- 首頁「推薦商品」區塊與其商品流，位於 REQ-003 商品帶之後（新增，不取代）
- 商品流自動分批載入：每批 20 個，共 5 批（100 個）
- 載入失敗時可在原處重試，已載入的商品保留
- 商品流虛擬化：只渲染視窗附近的商品卡
- 欄數：`matchMedia('(min-width: 1024px)')` 成立時 5 欄，否則 2 欄；JS（虛擬化計算）與 CSS（排版）使用同一條件

### 應該（Should）

- 【UX 優化】從商品頁按瀏覽器返回首頁時，恢復已載入的批數與捲動位置

### 不在範圍內（Out of scope）

- 瀑布流（不等高卡片）排版
- 真正無上限的商品流（本需求為功能示意，見目標）
- 搜尋頁、商品頁的無限捲動（搜尋頁維持分頁，REQ-001）
- 個人化推薦（REQ-003 已排除）
- 頂端服務連結列（APP 下載、書店等）：不渲染
- 回到頂端按鈕

## 版頭規格

| 項目       | 展開版（`scrollY <= 0`）                                                                                                                   | 收合版（`scrollY > 0`）                               |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------- |
| 高度       | 109px                                                                                                                                      | 64px                                                  |
| 內容       | 第一列（logo、搜尋框、購物車與數量）＋ 分類導覽                                                                                            | 只有第一列；分類導覽不渲染可見內容（`display: none`） |
| 定位       | `position: fixed; top: 0`                                                                                                                  | 同左                                                  |
| 主內容預留 | 外層容器 `.site`（不是 `<main>`）`padding-top: 109px`，固定不隨版型改變，切換時內容不位移；REQ-004「版頭與容器之間沒有間隔」在頂端時仍成立 | 同左                                                  |
| 切換動畫   | 無；高度在切換當下即為 109px 或 64px                                                                                                       | 同左                                                  |
| 錨點預留   | `scroll-padding-top: 64px`（錨點捲動後必為收合版）                                                                                         | 同左                                                  |

- `scrollY` 為負值（iOS 回彈）視為頂端；小數值依 `> 0` 判斷。
- 焦點在搜尋框時，版頭仍依 `scrollY` 照常切換。
- 整份文件中 `role=searchbox` 的元素恆為 1 個（含搜尋頁，搜尋頁不另放搜尋框）。
- 搜尋框的送出、導頁與預填行為沿用 REQ-001（版頭搜尋框，REQ-001#AC1），本需求不另行規定；兩種版型皆適用。
- 購物車與數量的顯示沿用 REQ-002（版頭購物車數量徽章），本需求不另行規定。
- 「跳到主要內容」連結的目標為 `<main id="main">`。
- 版頭的寬度、底色、第一列與分類導覽的內容和樣式沿用 REQ-004，本需求只規定定位、收合與高度。

## 商品流規格

| 項目       | 規格                                                                                                                                                        |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 資料來源   | `GET /api/home/feed?page=`（待 RD 以 CR 加入 API-001，見「限制」）                                                                                          |
| 第 1 批    | 第 1 批回應前先渲染標題 `<h2>推薦商品</h2>` 與高度 1 列（列高）的預留區；預留區進入觸發區時請求第 1 批（比照 REQ-003#AC3 延遲且不跳動）                     |
| 下一批     | 偵測元素進入觸發區時請求；請求完成後（包括因欄數改變而重新排版後）若偵測元素在觸發區內，繼續請求，直到到底                                                  |
| 到底       | 以最近一次成功回應的 `page` 與 `totalPages` 判斷，`page >= totalPages` 即到底；不寫死 5。回應的 `page` 與請求的不一致時視為錯誤（同 AC6 的失敗）            |
| 並行       | 同一時間最多 1 個商品流請求在進行中，依序載入                                                                                                               |
| 不重複請求 | 一次首頁生命週期內，同一 `page` 成功的請求只有 1 次。使用者按「重試」、API-001 的自動重試不計入                                                             |
| 卡片高度   | 固定 px：≥ 1024px 為 380px，< 1024px 為 320px，列間距分別為 16px、12px；虛擬化以「列」為單位計算。品名最多 2 行並截斷；原價與折數那一行不論有無都保留高度   |
| 失敗狀態   | 失敗後偵測元素再次進入觸發區**不會**自動重試，只能按「重試」。網路錯誤與逾時同為失敗；逾時秒數依 API 的 CR                                                  |
| 重複商品   | 允許與上方商品帶重複；跨批次不重複（由 API 保證），前端遇重複 `id` 時保留第一次出現者，`aria-posinset` 依去重後的順序從 1 起算                              |
| 離線       | 以 `navigator.onLine` 與 `online`／`offline` 事件判斷。離線時不觸發請求；恢復連線後，若不在失敗狀態且偵測元素在觸發區內則自動接續（失敗狀態仍需按「重試」） |
| 商品資料   | 每個商品為 API-001 的 `ProductSummary`；價格依 BR-001#R1、R2、R3、R6 顯示；商品流不顯示限搶價（R5 不適用）                                                  |

## 限制

- 不新增 runtime 依賴；虛擬化自行實作，或另立 ADR 允許引入套件。
- 版頭在 `src/app/`，屬整合者範圍；商品流在 `features/home`。
- API-001 已核准，新端點須由 RD 以 CR 加入後，才能實作商品流的 API 層。CR 須定義：
  - 回應 `{ items: ProductSummary[]; page: number; pageSize: 20; totalPages: number; total: number }`
  - `page` 非正整數或超過 `totalPages` 時的行為
  - 跨批次 `id` 不重複的保證
  - 錯誤碼與重試沿用 API-001 既有的錯誤表
  - 逾時秒數（Q27）
  - 回應 `page` 與請求 `page` 一致
- 斷點 1024px 目前沒有 token；由整合者在 `styles/` 加上對應常數或註解（CSS 自訂屬性不能用於 media query）。
