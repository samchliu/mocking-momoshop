# BR-003：加入購物車規則

> **核准後即為權威。** 庫存與限購的最終判斷在後端（mock API 回 409）；前端規則是為了體驗，不是為了保證正確性。

## 規則

| #   | 規則                                                                                                                                                                                                                                                                        |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R1  | 商品有規格時，必須選定規格才能加入購物車                                                                                                                                                                                                                                    |
| R2  | 數量必須是整數，範圍為 1 到 min(該規格庫存, 每人限購數)。修正方式：輸入不是有限數字（含空白）時視為 1；非整數無條件捨去；結果再限制在 1 到上限之間                                                                                                                          |
| R3  | 所選規格庫存為 0 時，不得加入購物車，按鈕顯示「已售完」                                                                                                                                                                                                                     |
| R4  | 加入請求進行中，按鈕必須停用；同一時間對同一商品只能有一個加入請求                                                                                                                                                                                                          |
| R5  | 版頭數量採樂觀更新：送出時先加上，失敗時必須回到送出前的數量，並顯示失敗原因                                                                                                                                                                                                |
| R6  | 購物車數量 = 各品項數量總和；存在瀏覽器（localStorage），讀回時驗證格式，格式不符則視為空購物車。格式不符包含：不是物件、`lines` 不是陣列、任一列的 `productId` 不是字串、`variantId` 不是字串或 null、`quantity` 不是 ≥ 1 的整數，或兩列的 (`productId`, `variantId`) 相同 |
| R7  | 購物車中同規格的數量加上本次數量超過限購或庫存時，後端回 409，前端顯示「超過可購買數量」                                                                                                                                                                                    |

## 參數

| 參數                 | 值  | 使用於 | 備註                                    |
| -------------------- | --- | ------ | --------------------------------------- |
| defaultPurchaseLimit | 5   | R2     | 商品可個別設定（實站例：每人限購 1 組） |

## 理由

| 規則 | 為什麼                                   | 證據                |
| ---- | ---------------------------------------- | ------------------- |
| R2   | 避免送出必定失敗的請求                   | REF-002（每人限購） |
| R4   | 防止連點造成重複加入                     | —                   |
| R5   | 回饋即時，但不能讓錯誤狀態殘留           | —                   |
| R6   | localStorage 是使用者可竄改的輸入        | —                   |
| R7   | 庫存一致性是後端責任，前端必須能處理衝突 | —                   |

## 範例

| #   | 情境                                                | 預期結果                 | 規則 |
| --- | --------------------------------------------------- | ------------------------ | ---- |
| E1  | 庫存 3、限購 5，輸入 9                              | 數量修正為 3             | R2   |
| E2  | 輸入 0、-2、1.7、空白                               | 修正為 1、1、1、1        | R2   |
| E3  | 庫存 0                                              | 按鈕停用，顯示「已售完」 | R3   |
| E4  | 快速點擊 3 次                                       | 只送出 1 個請求          | R4   |
| E5  | 版頭為 2，加入 1 件但 API 失敗                      | 版頭回到 2，顯示錯誤     | R5   |
| E6  | localStorage 被改成 `{"x":1}`                       | 購物車視為空             | R6   |
| E7  | localStorage 中一列 `quantity` 為 0 或 1.5          | 購物車視為空             | R6   |
| E8  | localStorage 中兩列 (`productId`, `variantId`) 相同 | 購物車視為空             | R6   |
