# BR-002：搜尋、篩選、排序與分頁規則

> **核准後即為權威。** 規則由 mock API（API-001）執行；前端只負責把條件忠實地放進 URL 與請求。

## 規則

| #   | 規則                                                                                                                                                                                             |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| R1  | 關鍵字必須先正規化：NFKC（全形轉半形）、移除控制字元與 `<>`、合併連續空白、去頭尾空白、最多 100 字。正規化後為空字串時不得送出搜尋                                                               |
| R2  | 比對：關鍵字以空白拆成詞，**每個詞**都必須出現在「品牌 + 品名」中（不分大小寫）                                                                                                                  |
| R3  | 排序選項：`relevance` 綜合推薦（預設；命中詞出現在品名開頭者優先，其次總銷量）、`sales` 銷量、`newest` 新上市、`price_asc` 價格低→高、`price_desc` 價格高→低。同分時以商品 ID 排序，保證結果穩定 |
| R4  | 篩選：品牌可多選（品牌之間為 OR）；價格區間包含上下限；不同篩選之間為 AND。最低價大於最高價時自動對調                                                                                            |
| R5  | 每頁 20 筆。頁碼非正整數時視為 1；超過最後一頁時視為最後一頁                                                                                                                                     |
| R6  | 關鍵字、排序或任一篩選變更時，頁碼必須回到 1                                                                                                                                                     |
| R7  | 品牌件數（facet）依「關鍵字 + 價格區間」計算，**不含品牌條件本身**，讓使用者看得到切換到其他品牌會有幾筆                                                                                         |

## 參數

| 參數             | 值  | 使用於 | 備註                       |
| ---------------- | --- | ------ | -------------------------- |
| pageSize         | 20  | R5     | 實站約 30；mock 資料量較小 |
| maxKeywordLength | 100 | R1     |                            |

## 理由

| 規則 | 為什麼                                                              | 證據    |
| ---- | ------------------------------------------------------------------- | ------- |
| R1   | 輸入是不可信資料；全形／空白差異不應造成不同結果                    | —       |
| R2   | 多詞搜尋時 AND 比 OR 更符合「縮小範圍」的意圖                       | —       |
| R3   | 對應實站排序列；穩定排序避免分頁時商品重複或遺漏                    | REF-002 |
| R5   | 分享舊連結時商品數可能已變少，不應出現空白頁                        | —       |
| R6   | 條件改變後停留在第 7 頁會造成空結果或誤解                           | —       |
| R7   | 與實站「Apple (785)」的件數呈現一致，且是常見的 faceted search 做法 | REF-002 |

## 範例

| #   | 情境                         | 預期結果                                   | 規則 |
| --- | ---------------------------- | ------------------------------------------ | ---- |
| E1  | 輸入「　ＩＰＨＯＮＥ　 15 」 | 關鍵字為 `IPHONE 15`                       | R1   |
| E2  | 輸入「 」                    | 不送出搜尋                                 | R1   |
| E3  | 搜尋 `apple 256`             | 只回傳品牌或品名同時含 apple 與 256 的商品 | R2   |
| E4  | 價格區間 5000～1000          | 視為 1000～5000                            | R4   |
| E5  | 共 45 筆，URL page=9         | 顯示第 3 頁                                | R5   |
| E6  | 在第 3 頁改排序              | 回到第 1 頁                                | R6   |
| E7  | 已勾 Apple，查看品牌清單     | 其他品牌仍顯示件數（不受 Apple 篩選影響）  | R7   |
