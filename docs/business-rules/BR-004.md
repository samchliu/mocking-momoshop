# BR-004：購物車編輯與金額規則

> **核准後即為權威。** 本文件規範 `/cart` 購物車頁上的品項狀態、數量編輯、移除與金額。「加入購物車」與購物車的儲存格式仍由 BR-003 規範；畫面與互動細節（文案、焦點、版面）由 REQ-006 規範。

## 用語

| 用語     | 定義                                                                                                                                                                                                                       |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 選項     | 商品的 `variants` 中的一項（API-001 `Variant`）。BR-003 稱為「規格」；與 API-001 的規格表 `specs` 無關                                                                                                                     |
| 品項     | 購物車中的一列，以 (`productId`, `variantId`) 唯一識別。列表順序 = 儲存陣列順序                                                                                                                                            |
| 儲存數量 | 品項在 localStorage 中的 `quantity`（BR-003#R6）。依 CR-004，讀回時已保證為 ≥ 1 的整數且 (`productId`, `variantId`) 不重複                                                                                                 |
| 商品資料 | `GET /api/products/:id` 的回應（API-001 `ProductDetail`）。每個不同的 `productId` 只請求一次，同一 `productId` 的所有品項共用；每次進入 `/cart` 時重新請求，不使用先前頁面的快取                                           |
| 選項相符 | 下列兩者之一：(a) `variantId` 為 null 且商品 `variants` 為空陣列；(b) `variantId` 不為 null 且存在於商品 `variants`。其餘組合（`variantId` 為 null 但 `variants` 非空；`variantId` 不為 null 但不在 `variants`）為選項不符 |
| 單價     | 選項相符時：情況 (b) 為該選項的 `price`；情況 (a) 為商品的 `price`。一律取本次請求的商品資料，不保存加入時的價格，不套用限搶價                                                                                             |
| 庫存     | 選項相符時：情況 (b) 為該選項的 `stock`；情況 (a) 為商品的 `stock`                                                                                                                                                         |
| 上限     | min(庫存, 商品的 `purchaseLimit`)；`purchaseLimit` 一律取 API 回應，前端不使用 BR-003 的 `defaultPurchaseLimit`                                                                                                            |
| 有效數量 | min(儲存數量, 上限)；只對「可購買」狀態定義                                                                                                                                                                                |

## 品項狀態

每個品項在任一時刻恰屬於下列一種狀態，依序判斷，取第一個成立者：

| 狀態         | 條件                                                                    | 可勾選 | 計入總金額／結帳品項數 | 可改數量 | 可移除 |
| ------------ | ----------------------------------------------------------------------- | ------ | ---------------------- | -------- | ------ |
| 載入中       | 商品資料尚未有結果（含自動重試期間）                                    | 否     | 否                     | 否       | 是     |
| 已下架       | 商品資料請求回 404                                                      | 否     | 否                     | 否       | 是     |
| 載入失敗     | 商品資料請求以 404 以外的原因失敗（4xx、5xx、逾時、離線、回應格式錯誤） | 否     | 否                     | 否       | 是     |
| 選項已不存在 | 商品資料已載入，選項不符                                                | 否     | 否                     | 否       | 是     |
| 暫不開放購買 | 選項相符，`purchaseLimit` < 1                                           | 否     | 否                     | 否       | 是     |
| 已售完       | 選項相符，`purchaseLimit` ≥ 1，庫存 < 1                                 | 否     | 否                     | 否       | 是     |
| 可購買       | 選項相符，上限 ≥ 1                                                      | 是     | 是（已勾選時）         | 是       | 是     |

「已下架」「選項已不存在」「暫不開放購買」「已售完」合稱**不可購買**。

## 規則

| #   | 規則                                                                                                                                                                                                                                                |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R1  | 數量修正：輸入不是有限數字（含空白）時視為 1；非整數無條件捨去；結果再限制在 1 到上限之間。與 BR-003#R2 相同（以 CR-004 修正後的文字為準）                                                                                                          |
| R2  | 數量寫入時機：「−」「＋」每按一次，以有效數量 −1／+1 後依 R1 修正並寫入；數量輸入框在失焦或按 Enter 時依 R1 修正並寫入，即使結果等於目前有效數量也寫入；輸入中不寫入、不影響金額。有效數量為 1 時「−」停用，等於上限時「＋」停用；「−」不會移除品項 |
| R3  | 數量變更、移除、全部刪除只修改瀏覽器中的購物車（BR-003#R6），不呼叫 API。寫入 localStorage 失敗時不回滾、不提示：畫面維持變更後的狀態。不同步其他分頁的變更（其他分頁的寫入在下次讀取前不會反映，最後寫入者勝）                                     |
| R4  | 移除：刪除該品項一列，其他品項的數量與順序不變。全部刪除：刪除所有品項（含未勾選、載入中、載入失敗與不可購買的品項）                                                                                                                                |
| R5  | 勾選：只有可購買的品項可以勾選。勾選狀態只存在頁面記憶體，不寫入 localStorage；每次進入 `/cart` 時所有品項皆為勾選。以「取消勾選的品項」集合記錄，不在集合中的可購買品項即為勾選；品項被移除時自集合中移除                                          |
| R6  | 全選：有可購買品項且全部勾選時為勾選；部分勾選時為部分勾選；沒有任何勾選時為未勾選；沒有可購買品項時為未勾選且停用。目前為勾選時點擊，將購物車中所有品項（不論狀態）加入取消集合；否則清空取消集合                                                  |
| R7  | 品項小計 = 單價 × 有效數量，只對可購買品項計算。總金額 = 已勾選的可購買品項小計之和。一律整數運算；總金額 > `Number.MAX_SAFE_INTEGER` 時依 BR-001#R1 顯示 `—`                                                                                       |
| R8  | 結帳品項數 = 已勾選的可購買品項列數（不是數量總和）。結帳品項數為 0，或有任何品項處於載入中狀態時，結帳按鈕停用                                                                                                                                     |
| R9  | 有任何品項處於載入中狀態時，總金額不顯示數值，顯示「計算中」；全部品項都有結果後才顯示總金額                                                                                                                                                        |
| R10 | 儲存數量大於上限（上限 ≥ 1）時，畫面與金額使用有效數量並提示（文案見 REQ-006）；儲存數量不自動改寫，直到使用者依 R2 寫入                                                                                                                            |
| R11 | 版頭購物車數量徽章仍依 BR-003#R6：儲存數量總和，含所有狀態的品項，不使用有效數量                                                                                                                                                                    |

## 參數

無。

## 理由

| 規則 | 為什麼                                                                                                                       | 證據               |
| ---- | ---------------------------------------------------------------------------------------------------------------------------- | ------------------ |
| 狀態 | 載入中、暫時失敗與真正無法購買要分開，否則頁面一打開就把所有品項標成不可購買；`variantId` 為 null 但商品有選項違反 BR-003#R1 | BR-003#R1、API-001 |
| R1   | 與商品頁一致，避免購物車頁出現商品頁不允許的數量                                                                             | BR-003#R2          |
| R2   | 逐字寫入會讓使用者無法輸入兩位數；確定時一律寫入，讓 R10 的提示能被使用者消除                                                | —                  |
| R3   | 購物車存在瀏覽器（BR-003#R6），mock API 只有「加入」端點；不呼叫 API 就沒有網路失敗與回滾，也不需變更 API-001                | API-001            |
| R4   | 與實站「全部刪除」一致                                                                                                       | EXP-003 O4         |
| R5   | 進頁面即全選，使用者不需額外操作即可結帳；不持久化以避免變更 BR-003#R6 儲存格式                                              | —                  |
| R7   | 金額整數運算避免浮點誤差                                                                                                     | BR-001#R1          |
| R8   | 實站「結帳(N)」的 N 推論為列數；載入中無法確定金額，不允許結帳                                                               | EXP-003 O14、H2    |
| R9   | 部分加總會被誤認為最終金額                                                                                                   | —                  |
| R10  | 庫存可能在加入後減少；自動改寫使用者的購物車屬於未經同意的資料變更                                                           | —                  |
| R11  | 徽章代表「購物車裡有什麼」，不是「能結帳什麼」                                                                               | BR-003#R6          |

## 適用條件

`/cart` 購物車頁。R11 是對全站版頭徽章的既有規則（BR-003#R6）的重申，不新增版頭行為。

## 不在範圍內

運費、促銷、折價券、限搶價、原價與折數顯示、結帳流程、與後端同步購物車、跨分頁同步。

## 例外

無。
