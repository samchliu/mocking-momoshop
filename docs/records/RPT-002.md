# RPT-002：實作與實站差異分析、品質量測

## 目的

說明本實作與實站（REF-002 的觀察）有哪些**刻意的差異**、為什麼，以及上線前的品質量測結果。差異分三類：**刻意不做**（範圍取捨）、**刻意不同**（我們認為更好或更一致）、**簡化**（mock 環境的限制）。

## 環境與方法

- 實站：2026-11-20 以一般瀏覽器人工檢視（REF-002）；未自動化抓取（CDN 阻擋，未繞過）。
- 本實作：main 分支 production build（`vite build` + `vite preview`），mock 後端預設延遲 300ms。
- 量測：Lighthouse CI（desktop preset，每頁 3 次取中位數）、Playwright（desktop Chrome + Pixel 7）、Vitest。

## 結論

- 視覺還原刻意放在第二優先；差異集中在「範圍外」與「實站用語不一致」兩處，兩者都有對應的 REQ／BR 依據。
- CR-001 對齊版面骨架與商品頁後，Lighthouse 與 CLS 沒有退步；版頭由一列變兩列未造成版面跳動。
- 實作在**規則明確度**（價格、分頁、件數、限購）與**非功能面**（錯誤狀態、a11y、效能）上高於「照抄畫面」所需。
- 實站為 CSR、mock 為 CSR，Lighthouse 數字不可與實站直接比較（無真實網路、圖片為 inline SVG）。

## 後續

- 真實圖片後應量測 mobile preset 的 LCP，並導入 responsive `srcset`。
- 若要接真實後端：API-001 即契約，替換 `VITE_API_BASE_URL` 即可；BR-002／BR-003 的伺服端規則需由後端實作並以同一組測試案例驗證。
