# RPT-004：購物車頁（追加）的人機協作紀錄與實站差異

## 目的

購物車頁原本列為「刻意不做」（REQ-002「不在範圍內」）。核心範圍完成後，在約 120 分鐘的時間窗之外追加。本報告記錄：

1. 這次從實站觀察到合併的完整流程，以及 AI 在哪裡做了決定、哪裡由人決定。
2. 核准前歧義檢查（ADR-004）在這次的效果，以及這次**省略**了哪一步。
3. 購物車頁與實站的差異（RPT-002 已封存，差異記在這裡）。

值得記錄的幾處：

- **與已核准規則的矛盾**：REQ-006 起草時寫「不顯示折數」，與 BR-001#R2 直接衝突；BR-003#R2「最近的合法值」與 BR-003 自己的範例 E2 矛盾。前者以 D5（購物車頁完全不顯示原價，BR-001 不適用）解決，後者以 CR-004 修正 BR-003。
- **檢查者被限制不讀 REQ**：BR-004 的檢查者回報「勾選狀態未定義」，但 REQ-006 有寫。這說明 BR 本身沒有自足，回填時把勾選規則搬進 BR-004（R5、R6）。
- **可測性**：可存取名稱「移除 {品名}」在同一商品多個選項、或多個下架品項時會重複，`getByRole(name)` 無法寫測試。回填時新增「品項名稱」定義（選項以全形括號附加；取不到資料時為「商品 {productId}」）。

## 這次省略的步驟

- **回填後沒有重跑歧義檢查**就核准（PM 因時間要求「直接開工」）。RPT-003 的經驗是第二輪仍會找到 AI 回填時引入的矛盾，因此 REQ-006、BR-004 的回填內容未經獨立檢查。
- **購物車頁未納入 Lighthouse CI**（`lighthouserc.json` 只量首頁、搜尋、商品頁）。

## 實站差異（購物車頁）

實站依據：EXP-003（桌機版、登入後；手機版未觀察）。

| 項目                         | 實站                                                               | 本實作                                                                                              | 類型                           |
| ---------------------------- | ------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------- | ------------------------------ |
| 版頭                         | 精簡版頭：只有 logo 與「購物車」                                   | 沿用全站版頭（REQ-004）                                                                             | 刻意不同（少一種版型）         |
| 取貨方式分頁、出貨分組、運費 | 「宅配／超商取貨」分頁；「快速到貨」分組與免運門檻                 | 單一列表                                                                                            | 刻意不做（無配送資料）         |
| 品項                         | 勾選、圖、品號、出貨標籤、品名、規格連結、促銷狀態、「總計」與原價 | 勾選、圖、品名（含選項）連到商品頁、單價、數量、小計；不顯示原價與折數（D5）                        | 簡化                           |
| 數量                         | 「− n ＋」                                                         | 同；輸入框失焦或 Enter 才寫入；超過目前庫存時以上限計算並提示（BR-004#R1、R2、R10）                 | 一致 + 規則明確化              |
| 移除／全部刪除               | 「移除」；區塊標題列「全部刪除」                                   | 「移除」直接刪除並 toast；「全部刪除」以 Dialog 確認                                                | 一致 + 防誤刪                  |
| 勾選                         | 部分預設勾選                                                       | 進入頁面全部勾選，不持久化（BR-004#R5）                                                             | 刻意不同                       |
| 無法購買的品項               | 價格變淡、只剩「−」與「移除」（原因未確認）                        | 分成載入中、已下架、載入失敗（可重試）、選項已不存在、暫不開放購買、已售完；不可勾選、不計入金額    | 規則明確化（BR-004 品項狀態）  |
| 結帳列                       | 固定在底部：總金額、已折金額、明細、「結帳(N)」                    | 固定在底部：總金額（載入中顯示「計算中」）、「結帳(N)」（N 為列數）；點擊只提示「結帳功能尚未開放」 | 簡化（無折扣明細、無結帳流程） |
| 促銷、折價券、組合商品、追蹤 | 有                                                                 | 無                                                                                                  | 刻意不做                       |

## 結論

- 歧義檢查在這次同樣有效：兩處與已核准規則的矛盾、一處無法寫測試的可存取名稱，都在寫程式前被找出。
- 這次由 AI 做的決定比前幾次多（D2–D14），PM 以概括同意的方式核准；決策都寫進 REQ-006 的決策表，可追溯、可走 CR 修改。
- 測試全綠不代表交付品質：效能問題（#1）是在交付前 review 才發現。
